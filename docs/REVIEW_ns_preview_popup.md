## Findings

### F1 — stale names in the debounce window (accepted)
**Finding.** Between a selection change and its reply, `view.reportPreviewNames` still holds the
PREVIOUS selection's names and the button stays visible; the dialog fills at open time and is never
repainted. Open "view namespaces" inside the 400 ms window → the superseded selection's namespaces are
shown as the answer for the new one — the product's exact failure mode.
**Re-check.** Traced `schedulePreview`: the valid-selection path armed the timer without clearing the
names or hiding the button. The modal makes the background inert, so the only path is
closed→change→click-in-window, which the fix covers.
**Decision.** Accepted. `schedulePreview` clears the names and hides the affordance until the fresh
reply lands; the count text keeps its #107 self-correcting behaviour.

### F2 — a same-cluster Back strands the open dialog (accepted)
**Finding.** `closeNsPreview` ran only in `applyPosition`'s cluster-change branch, so a same-cluster
browser Back from Reports left the modal floating over a page with no selection.
**Re-check.** `applyPosition` is the navigation chokepoint (selector, popstate, hashchange all arrive
there — its own comment says so). One guarded line at the end closes it on any move off the reports page.
**Decision.** Accepted.

### F3 — focus lost after a poll repaint (accepted; test made robust)
**Finding.** `showModal()` memorises the opener node; the 60 s poll's `render()` replaces `#main`, so
the native focus-return targets a detached element and drops focus to `<body>`.
**Re-check.** Confirmed the poll (`POLL_INTERVAL_MS = 60000` → `render()`). The `onclose` re-aim by id
is correct — but the first test run failed because the assertion read `document.activeElement`
*instantly*, before the async focus settled (the DIAG showed focus DID land on the button a round-trip
later). The fix is sound; the **test** was the flake. Changed the assertion to
`wait_for_function` on the button being focused (still fails-before: without the fix it never becomes
true and times out). Stable across repeated runs.
**Decision.** Accepted, with the test corrected to wait for the async focus rather than assert instantly.

## Not fixed (accepted debt)
- **Padding-click close.** A click on the dialog's 18–20px padding targets the dialog and closes it.
  Read-only dialog, one click reopens the same names, the list area targets its own `ul`/`li`, and
  Close + Escape are the advertised paths. Both reviewers judged it acceptable; no fix.
- **`aria-describedby` on the count line.** `#ns-preview-count` is not referenced by
  `aria-describedby`, so a screen reader hears the title then walks to the count. The platform reads
  it in document order anyway; noted as a follow-up, no snippet warranted.
