## 0. The cross-lens seam: what `/api/whoami` must carry

Everything below consumes one contract, owned by the API lens. The UI reads:

```json
{
  "user": "jane.smith",
  "email": "jane.smith@example.com",
  "authenticated": true,
  "logout_url": "/oauth/sign_out",
  "session": { "expire_seconds": 1800, "refresh_seconds": 300 }
}
```

- `logout_url`: `null` whenever `authenticated` is false (research doc, Feature 2). No URL, no
  logout control — the page never offers to end a session that does not exist.
- `session`: `null` when the proxy is disabled. `expire_seconds` mirrors `-cookie-expire`;
  `refresh_seconds` mirrors `-cookie-refresh`, `0` when refresh is disabled.
- The UI is defensive about every field: an older API without `session` (or a deployment where the
  lab test forced `refresh: 0`) simply leaves the countdown disarmed — see §7. No field here is
  load-bearing for the page to render.

Field names are the seam; if the API lens chose different ones, reconcile to ITS names — the UI
snippets below reference `who.session.expire_seconds` / `who.session.refresh_seconds` /
`who.logout_url` and are the only consumers.

## 1. Suspending the 30s poll on real inactivity

### What is wrong today, precisely

`index.html` line 2490: `setInterval(() => refresh({ auto: true }), 30000);` — unconditional, no
`visibilitychange` handling anywhere in the file (verified: zero occurrences). Every 30s tick makes
4+ real HTTP requests through the proxy. The proxy re-stamps the session cookie on any request whose
session age exceeds `cookie-refresh`, so an open tab slides the cookie forever and the 30-minute
idle timeout can never fire. The flags without this change ship a control that does nothing.

### The activity model

**What counts as activity: `pointerdown`, `keydown`, `wheel`.** Each is a discrete, deliberate act —
a click/tap (pointer events unify mouse and touch, so no separate `touchstart` is needed), a
keypress, a scroll gesture. What deliberately does NOT count:

- **`pointermove` — the trap named in the brief.** It fires continuously (cost), and it fires
  *without a human*: sub-pixel jitter from a hand resting on a mouse, desk vibration, and — decisive
  for this page — browsers dispatch a synthetic `pointermove` when layout changes under a stationary
  cursor. This page repaints itself on every poll, so `pointermove` would re-arm the idle timer from
  the page's own repaint, forever, on exactly the unattended-workstation the timeout exists for.
- **`scroll` — the same trap one step removed.** The poll repaint replaces `#main`'s innerHTML; when
  the new content is shorter, the browser clamps the scroll position and fires a `scroll` event the
  user did not cause. Wheel/trackpad scrolling emits `wheel`, keyboard scrolling emits `keydown`, so
  real reading is still covered. The one uncovered gesture — dragging the scrollbar itself for
  minutes without ever clicking or wheeling — is marginal, and the countdown modal (§2) is its
  safety net.
- **`visibilitychange` to visible IS treated as activity**: choosing this tab is a human act.

**Tab hide/show:** a hidden tab never polls (`document.hidden` guard). On becoming visible the page
records activity and runs one catch-up tick.

**No thundering herd on resume**, by construction: `setInterval` coalesces missed ticks in a hidden
tab (at most one pending fire), and every path that could trigger a catch-up — the interval, the
first interaction after idleness, `visibilitychange` — funnels through `pollTick()`, which refuses
to start an auto refresh within `POLL_MS` of the previous one. Three simultaneous triggers collapse
to one request cycle.

**`pollTick()` returns a reason string** (`"over" | "warned" | "hidden" | "idle" | "fresh" |
"refreshed"`). That return value is the test surface and the debugging surface: a wrong suspension
is diagnosable from one `pollTick()` call in the console instead of by watching the network tab for
a minute.

### The security arithmetic (defaults: expire 30m, refresh 5m, `IDLE_SUSPEND_MS` 2m)

Last human input at `T`. Polls continue until `T+2m`; the last request that can re-stamp the cookie
is sent by `T+2m`, and the stamp it refreshes is at latest that moment (at earliest `T+2m−5m`). The
cookie therefore dies between `T+27m` and `T+32m` — the "≈30 minutes of true inactivity" the tighter
default is buying, within +2m. A larger suspend window widens that bound one-for-one, which is why
2 minutes and not 10; smaller would make the dashboard feel broken to someone reading a long table.

The snippets for this section are S4/S5 in §6-adjacent placement below (§5.5 "Snippet placement"),
since the poll, the model and the modal share one block of code.

## 2. The countdown pop-up and the model behind it

### The problem restated as an invariant

The cookie is HttpOnly and the proxy forwards no session-age header, so neither the browser nor the
FastAPI app can observe the deadline. Any countdown is a model. The design goal, chosen over
"accurate on average": **the model must never claim more time than the session truly has.** Warning
early is an annoyance bounded below; warning late is a silent logout mid-read, unbounded in cost on
a governance dashboard. So the model maintains a *provable lower bound* on the deadline and shows
that.

### The interval model

Track a wall-clock interval `[lo, hi]` guaranteed to contain the instant the proxy last stamped the
cookie (`trueStamp`). The displayed deadline is `lo + expire` — a floor, because
`lo ≤ trueStamp ⇒ lo + expire ≤ trueStamp + expire`.

- **Page load / whoami arrival.** The request that just completed went through the proxy: if the
  session was older than `refresh` it was re-stamped by that very request, otherwise the previous
  stamp is at most `refresh` old. Either way `trueStamp ∈ [sentAt − refresh, now]`, so
  `lo = sentAt − refresh, hi = now`.
- **Every successful API response**, with `sentAt` recorded before the fetch (the proxy stamped
  while the request was in flight, so send time is the safe floor and receive time the safe
  ceiling):
  - `sentAt − hi > refresh` → the session was *provably* older than `refresh` when the proxy handled
    it, so it *certainly* re-stamped: `[lo, hi] = [sentAt, now]`. The model is now exact.
  - else `sentAt − lo > refresh` → it *may* have re-stamped: if it did, `trueStamp ≤ now`; if it did
    not, the session was younger than `refresh`, i.e. `trueStamp ≥ sentAt − refresh`. Hull:
    `[max(lo, sentAt − refresh), now]`.
  - else → the session was provably younger than `refresh`; no re-stamp; interval unchanged.

The naive alternative — "assume a re-stamp whenever the *model's* age exceeds `refresh`" — is
unsound: worked example with refresh = 5m — page loads when the true session age is 4m (no re-stamp
at load), naive model assumes age 5m, and at load+ε concludes a re-stamp that never happened,
putting its floor *after* the truth and its warning *after* the expiry. The maybe-branch above is
what closes that hole; a test in §6 replays this exact sequence.

**Convergence and the error bound.** `hi − lo ≤ refresh` always, so the warning is early by at most
`cookie-refresh` (5m at defaults) — and only until the first response after a gap longer than
`refresh`, which snaps the model exact. In the idle scenario that actually shows the modal, polls
stopped at `T+2m`, the modeled deadline is ≈`T+27m` against a true death in `(T+27m, T+32m]`: the
modal appears ≈`T+25m`, counts 2 minutes, and is never late.

**Multi-tab truthfulness.** Tabs share the cookie but not, natively, the model — a background tab's
frozen model would warn while a foreground tab keeps the session alive. The model is therefore
shared through `localStorage` (same origin, same machine, same clock): every model improvement is
written to `gsd:session-stamp`, and every `sessionTick()` merges a fresher floor from it. Soundness
holds because a stamp written by any tab is a valid bound for all of them, storage failure
(disabled/quota) degrades to tabs modelling alone, and the modal auto-closes if a merge proves the
warning moot — a warning left on screen after another tab extended the session would be the page
lying.

### When the model drifts — the two interesting cases

- **Laptop sleep** (timers freeze, `Date.now()` jumps forward on wake): all model arithmetic is in
  wall-clock time, never accumulated ticks, so the stored `[lo, hi]` stays *correct* through sleep —
  on wake the next 1s tick recomputes the remaining time from `Date.now()` and lands in the right
  state immediately: still armed, straight to the warning, or straight to the over-state if the
  deadline passed while the lid was closed. A forward *clock jump* (NTP) is indistinguishable and
  equally safe: it can only shrink the modeled remaining time — early, never late.
- **Backward clock jumps** are the dangerous direction (the deadline appears to recede). The 1s
  ticker keeps `lastTickAt`; any tick observing `now < lastTickAt` shifts `lo` and `hi` down by the
  observed gap. That over-corrects (early, safe) and costs nothing when it never happens.

### When the model is wrong anyway

- **Too early** (the only direction construction allows, ≤5m): the modal appears with real time left.
  Cost: an interruption. "Stay signed in" resolves it — see below — and resets the model to exact.
- **Modeled zero reached**: the truth is somewhere in `[modeled 0, modeled 0 + 5m]`. The page must
  NOT probe to find out: **a probe is a request, and a request re-stamps a still-live cookie — an
  automatic probe would extend the session without a human present, quietly rebuilding the bug this
  whole feature removes.** So at zero the dialog switches to the over-state and *says the truth*:
  "Your session has ended, or is about to." One click ("Sign in again", a plain navigation to `/`)
  recovers either way — straight in if the cookie still breathes, through the OAuth flow if not.
  The same honesty rule from research Finding 2 applies: the over-state notes that OpenShift SSO may
  sign you back in without a password.

### What the modal says and does

- **Appears** when the modeled remaining time ≤ `SESSION_WARN_MS` (2 minutes). Only genuinely idle
  sessions ever get there: an active reader's requests keep re-stamping the model and the warning
  recedes ahead of them.
- **Warning state**: title "Your session is about to end", one sentence of why, a `m:ss` countdown
  of the modeled floor (comment documents that the true remaining time is this or up to `refresh`
  more — the safe direction to under-promise), a primary **Stay signed in** button, and **Sign out
  now** (the GET logout link) when `logout_url` exists.
- **Stay signed in** = `recordActivity(); close; refresh()`. The refresh is un-`auto`'d — a human
  choice, so it marks the interaction for the usage counter like any click, repaints the stale data,
  and its first response hits the certain-re-stamp branch (the gap exceeds `refresh` by
  construction), resetting the model to exact and the deadline to a full `expire`.
- **While the modal is open, polling stays off** (`pollTick` → `"warned"`) and page activity cannot
  dismiss it — `showModal()` makes the page behind inert, and extension requires a deliberate act
  aimed at the dialog. An accidental desk-bump must not extend a session on an unattended machine.
- **Escape = Stay signed in** (the `cancel` event, intercepted). Deliberate divergence from
  "Escape merely dismisses": a keypress aimed at this dialog is proof of presence, and
  dismiss-but-die would manufacture the silent mid-read logout the dialog exists to prevent. In the
  over-state Escape closes normally — the page behind is dead but still readable and copyable.

## 3. When the session is already dead: making the failure legible

### What the wrapper does today (read, not assumed)

`api()` (index.html lines 237–248) is `fetch(path, { headers })` — default `redirect: "follow"` —
then `if (!res.ok) throw` with the status, else `res.json()`. On a dead session the proxy answers
the API request with a redirect to its sign-in page; fetch follows it same-origin, gets HTML with a
2xx, `res.ok` passes, and **`res.json()` throws `SyntaxError: Unexpected token '<'`**, which
`refresh()`'s catch (line 2453) paints as *"Dashboard API error: Unexpected token '<'…"* over a note
suggesting "the object may have been deleted" — three lies in one card. If the redirect chain ever
leaves the origin (the OAuth server), CORS makes fetch reject with `TypeError: Failed to fetch`,
which paints the same card with a different wrong message.

### The fix: refuse to follow, and type the error

`redirect: "manual"` is safe here because the FastAPI app never redirects `/api/*` (exact routes, no
trailing-slash aliases in use) — the only redirect an API request can meet is the proxy answering
for a dead session, and `res.type === "opaqueredirect"` detects it without ever loading the sign-in
page or touching the OAuth server. A `text/html` body on any status is the belt-and-braces for a
proxy that serves its sign-in page with 200 or 403 instead of redirecting.

**S1 — complete replacement of `api()`.** File `local-development/gsd/static/index.html`; anchor:
the function currently spanning lines 237–248, directly beneath the comment block ending
`…480 requests an hour from a tab left open on an empty desk. */` (the comment stays).

```js
async function api(path, mark) {
  const headers = { Accept: "application/json" };
  if (mark) headers["X-GSD-Interaction"] = "1";
  // Recorded BEFORE the fetch: if the proxy re-stamps the cookie it does so while this request
  // is in flight, so send time is the safe floor for the session model and receive time the
  // safe ceiling — see noteAuthedResponse().
  const sentAt = Date.now();
  // redirect: "manual", because the app never redirects /api/* — the only redirect one of these
  // requests can meet is the oauth-proxy bouncing a dead session toward its sign-in page.
  // Following it (the old default) returned that page's HTML with a 200, and res.json() then
  // reported the end of the session as "Unexpected token '<'". Refusing to follow makes a dead
  // session detectable without loading the sign-in page or touching the OAuth server at all.
  const res = await fetch(path, { headers, redirect: "manual" });
  const ct = (res.headers.get("content-type") || "").toLowerCase();
  // HTML on any status is the same verdict: a proxy configured to serve its sign-in page
  // directly (200 or 403) instead of redirecting must not fall through to the generic card.
  if (res.type === "opaqueredirect" || ct.includes("text/html")) {
    const err = new Error(`signed out — the login page answered for ${path}`);
    err.sessionExpired = true;
    throw err;
  }
  if (!res.ok) {
    // The status rides on the error so a caller can tell a DESIGNED refusal from a fault.
    const err = new Error(`${res.status} ${res.statusText} on ${path}`);
    err.status = res.status;
    throw err;
  }
  // Only an OK JSON response teaches the session model: it provably traversed the proxy with a
  // live cookie. Error statuses are left out — they prove it too, but nothing is lost by being
  // conservative and the model stays a floor either way.
  noteAuthedResponse(sentAt);
  return res.json();
}
```

**S2 — the catch block in `refresh()`.** Same file; replace the block from the unique line
`  } catch (err) {` (line 2453) through the function's closing brace. Everything except the first
two added lines is the existing code, unchanged:

```js

      <div class="filterbar-note" style="margin-top:6px">
```

`sessionEnded("confirmed")` (S4) latches `sessionOver`, stops all polling permanently
(`pollTick` → `"over"`), and shows the over-state dialog. "confirmed" vs "modeled" matters: a
modeled end can be un-latched when another tab's shared stamp proves the session alive; a confirmed
one (the proxy itself answered) cannot.

### 5.2 Accessibility decisions, one by one

- **Focus trap / inert page**: native `showModal()` — the platform's trap, not a hand-rolled one.
- **Initial focus**: `autofocus` on "Stay signed in" (the safe default action) in the warning
  state; explicit `.focus()` on "Sign in again" in the over-state, where the stay button is hidden.
- **Focus restore**: the element focused at open is remembered and restored on `close` (any close
  path — Escape, stay, programmatic) with `preventScroll: true`, matching the filter bar's restore
  idiom; if the poll repainted it away, focus lands on the always-present Refresh button rather
  than `<body>`.
- **Escape**: the `cancel` event. Warning state → `preventDefault()` + stay-signed-in (§2 rationale:
  a keypress aimed at the dialog is presence; dismiss-but-die manufactures the silent logout).
  Over-state → closes normally.
- **Name and description**: `aria-labelledby`/`aria-describedby` point at the visible title and
  body, which JS swaps per state — the accessible name always matches what sighted users read.
- **The live countdown**: the classic mistake is `aria-live` on the ticking counter — sixty
  announcements a minute. Here the counter is `aria-hidden` and a visually-hidden `role="status"`
  region (polite, atomic) announces at three moments only: on open ("about N minutes"), at 60s, and
  at 30s. The over-state needs no live announcement: focus moves to the "Sign in again" link, which
  reads the new title and description through the dialog's labelling.
- **Contrast**: every pair on the dialog surface is an already-tested token pair (§4); verified
  behaviourally in both themes in §6.
- **Reduced motion**: nothing animates; the global `prefers-reduced-motion` collapse needs no help.

### 5.3 The session code

**S4b — the session section.** File `local-development/gsd/static/index.html`; insert immediately
after the unique line `$("refresh").onclick = refresh;` (line 2469) and before the `/* Boot from
the URL…` comment block:

```js
/* ── Session lifetime: idle-aware polling and the countdown model ─────────────────────────
   The proxy re-stamps the session cookie on any request older than cookie-refresh, so the old
   unconditional 30s poll made the idle timeout unreachable: an open tab slid the cookie forever,
   including on an unattended, unlocked workstation — the exact case the timeout is for. The
   poll therefore runs only while a human is demonstrably present, and a model of the deadline
   (which an HttpOnly cookie makes unobservable) drives a warning before the end.

   The model is a provable FLOOR on the deadline: [sessLo, sessHi] always contains the instant
   the proxy last stamped the cookie, so lo + expire never overstates the time left. Early by at
   most cookie-refresh (an interruption); late never (a silent logout mid-read). */

const POLL_MS = 30_000;
/* Two minutes: long enough that reading a long table never pauses the data underneath it,
   short enough that the idle-logout promise stays honest — the last poll that can re-stamp the
   cookie is sent within this window of the last human input, so true idle logout lands between
   expire-refresh and expire+IDLE_SUSPEND after the person left (27–32 minutes at the shipped
   defaults, against the "about 30" the values file promises). */
const IDLE_SUSPEND_MS = 120_000;
const SESSION_WARN_MS = 120_000;
const SESSION_STAMP_KEY = "gsd:session-stamp";

let lastActivityAt = Date.now();
let lastAutoRefreshAt = 0;
/* null until /api/whoami proves there is a proxy session to model — local development and
   proxy-disabled installs keep every branch below inert. */
let sessionModel = null;   // { expireMs, refreshMs, lo, hi }
/* false | "modeled" | "confirmed". Modeled ends can be un-latched by another tab's shared
   stamp proving the session alive; a confirmed one (the proxy itself answered for a request)
   cannot. */
let sessionOver = false;
let sessionLogoutUrl = null;
let sessionReturnFocus = null;
let sessionLastAnnouncedMs = Infinity;
let lastTickAt = Date.now();

/* pointerdown, keydown, wheel — discrete, deliberate acts. NOT pointermove: it fires from
   sub-pixel jitter of a resting hand, and browsers synthesize one when layout changes under a
   stationary cursor — which this page does to itself on every poll, so pointermove would re-arm
   the idle timer from our own repaint forever. NOT scroll: the repaint clamps the scroll
   position when content shrinks and fires it with nobody there; wheel and keydown cover real
   reading. Capture phase, because several tables stopPropagation() in their own handlers and
   the window would otherwise never hear those clicks. */
function recordActivity() {
  const wasIdle = Date.now() - lastActivityAt > IDLE_SUSPEND_MS;
  lastActivityAt = Date.now();
  // One catch-up so the page is fresh the moment someone returns — pollTick's own guard
  // collapses this, the interval and visibilitychange into a single request cycle.
  if (wasIdle) pollTick();
}
for (const type of ["pointerdown", "keydown", "wheel"]) {
  window.addEventListener(type, recordActivity, { capture: true, passive: true });
}

document.addEventListener("visibilitychange", () => {
  if (document.hidden) return;
  // Choosing this tab is a human act. Session state first: a deadline that passed while the
  // tab was hidden must surface as the over-state, not as one more poll re-stamping a cookie
  // nobody is using.
  sessionTick();
  recordActivity();
  pollTick();
});

/* The 30s poll, gated. Returns WHY it did or did not fetch — that string is the test surface
   and the console diagnosis for "why is my dashboard stale". {auto: true} because background
   polling must not register as somebody using the page (the usage counter's rule). */
function pollTick() {
  if (sessionOver) return "over";
  // An open warning means the reader is being asked whether they are present; a poll here
  // would re-stamp the cookie and answer for them.
  if ($("session-dialog").open) return "warned";
  if (document.hidden) return "hidden";
  if (Date.now() - lastActivityAt > IDLE_SUSPEND_MS) return "idle";
  // The herd guard: interval, catch-up and visibilitychange can all land in the same instant
  // when a tab wakes; whichever arrives first fetches and the rest see "fresh". The 1s slop
  // keeps ordinary interval jitter from skipping a legitimate tick.
  if (Date.now() - lastAutoRefreshAt < POLL_MS - 1_000) return "fresh";
  lastAutoRefreshAt = Date.now();
  refresh({ auto: true });
  return "refreshed";
}

/* Arms the model from the whoami contract. refresh_seconds of 0 (refresh disabled — the
   provider=openshift contingency) leaves it DISARMED on purpose: with no re-stamping the
   expiry is absolute and anchored to a login instant this page cannot observe, so any
   countdown would be a guess; the signed-out failover in api() carries that mode alone. */
function initSession(who, sentAt) {
  const s = who && who.session;
  if (!who || !who.authenticated || !s || !s.expire_seconds || !s.refresh_seconds) return;
  // The whoami request itself just traversed the proxy: either it re-stamped the cookie, or
  // the previous stamp was younger than refresh — so the stamp lies in [sentAt-refresh, now].
  sessionModel = {
    expireMs: s.expire_seconds * 1000,
    refreshMs: s.refresh_seconds * 1000,
    lo: sentAt - s.refresh_seconds * 1000,
    hi: Date.now(),
  };
}

/* Every OK JSON response teaches the model, mirroring the proxy's own arithmetic
   (oauthproxy.go: re-stamp iff sessionAge > CookieRefresh). sentAt, not now, as the floor:
   the proxy stamped while the request was in flight.
     certain re-stamp (age exceeded refresh even by the OLDEST possible stamp) -> exact;
     maybe (only the newest bound rules it in) -> hull of both outcomes, floor rises;
     provably young -> nothing happened, learn nothing.
   The maybe-branch is load-bearing: assuming a re-stamp whenever the MODEL's age crosses
   refresh puts the floor past the truth after one unlucky page load, and the warning after
   the expiry — the unsound direction. A test replays that exact sequence. */
function noteAuthedResponse(sentAt) {
  if (!sessionModel || sessionOver) return;
  const m = sessionModel;
  if (!m.refreshMs) return;
  const now = Date.now();
  if (sentAt - m.hi > m.refreshMs) { m.lo = sentAt; m.hi = now; }
  else if (sentAt - m.lo > m.refreshMs) { m.lo = Math.max(m.lo, sentAt - m.refreshMs); m.hi = now; }
  else return;
  // Tabs share the cookie, so they share the model: a background tab warning while a
  // foreground tab keeps the session alive would be the page lying. Storage denied just means
  // tabs model alone — every stamp any tab writes is a valid bound for all of them.
  try { localStorage.setItem(SESSION_STAMP_KEY, JSON.stringify({ lo: m.lo, hi: m.hi })); }
  catch (e) { /* private mode / quota: single-tab modelling is still sound */ }
}

function mergeSharedStamp(now) {
  let shared = null;
  try { shared = JSON.parse(localStorage.getItem(SESSION_STAMP_KEY) || "null"); }
  catch (e) { return; }
  if (!shared || typeof shared.lo !== "number" || typeof shared.hi !== "number") return;
  // Clamped to now: same machine, same clock, but a corrupt future stamp must not push the
  // deadline past what any tab actually proved.
  const lo = Math.min(shared.lo, now);
  if (lo > sessionModel.lo) {
    sessionModel.lo = lo;
    sessionModel.hi = Math.max(Math.min(shared.hi, now), lo);
  }
}

function fmtCountdown(ms) {
  const s = Math.max(0, Math.ceil(ms / 1000));
  return `${Math.floor(s / 60)}:${String(s % 60).padStart(2, "0")}`;
}

/* The 1s heartbeat. Cheap when disarmed, and it is also the drift detector: everything is
   wall-clock (Date.now()), never accumulated ticks, so laptop sleep costs nothing — on wake the
   next tick recomputes and lands in the right state directly. Forward clock jumps only shrink
   the modeled remainder (early, safe); a BACKWARD jump would inflate it, so any tick that
   observes time running backwards shifts the model down by the gap — over-correcting toward
   early, which is the safe direction. Hidden tabs get throttled ticks; visibilitychange runs
   one immediately on return. */
function sessionTick() {
  const now = Date.now();
  const gap = now - lastTickAt;
  lastTickAt = now;
  if (!sessionModel) return "disarmed";
  if (gap < 0) { sessionModel.lo += gap; sessionModel.hi += gap; }
  mergeSharedStamp(now);
  const remaining = sessionModel.lo + sessionModel.expireMs - now;
  if (sessionOver === "confirmed") return "over";
  if (sessionOver === "modeled") {
    // Another tab's shared stamp can prove a modeled end wrong; a confirmed one it cannot.
    if (remaining > SESSION_WARN_MS) { sessionOver = false; closeSessionModal(); return "armed"; }
    return "over";
  }
  if (remaining <= 0) { sessionEnded("modeled"); return "ended"; }
  if (remaining <= SESSION_WARN_MS) { openSessionModal(remaining); return "warning"; }
  // A warning made moot (stay in another tab, merge above) must not stay on screen lying.
  if ($("session-dialog").open) closeSessionModal();
  return "armed";
}

function openSessionModal(remaining) {
  const dlg = $("session-dialog");
  $("session-count").textContent = fmtCountdown(remaining);
  if (!dlg.open) {
    sessionReturnFocus = document.activeElement;
    // Full state reset, because the same element served the over-state on a previous cycle.
    $("session-title").textContent = "Your session is about to end";
    $("session-desc").textContent =
      "You have been inactive for a while, so this dashboard is about to sign you out to " +
      "protect the access data it shows.";
    $("session-remaining").hidden = false;
    $("session-stay").hidden = false;
    $("session-signin").hidden = true;
    $("session-signout").hidden = !sessionLogoutUrl;
    dlg.showModal();
    $("session-stay").focus();
    // Announced ONCE at open, then at two milestones below — never per second. The visible
    // counter is aria-hidden for exactly that reason.
    $("session-announce").textContent =
      `Inactive session: you will be signed out in about ${Math.ceil(remaining / 60_000)} ` +
      `minutes unless you choose to stay signed in.`;
    sessionLastAnnouncedMs = remaining;
    return;
  }
  for (const mark of [60_000, 30_000]) {
    if (remaining <= mark && sessionLastAnnouncedMs > mark) {
      $("session-announce").textContent =
        `About ${Math.round(mark / 1000)} seconds until sign-out.`;
      break;
    }
  }
  sessionLastAnnouncedMs = remaining;
}

function closeSessionModal() {
  const dlg = $("session-dialog");
  if (dlg.open) dlg.close();
}

function staySignedIn() {
  recordActivity();
  closeSessionModal();
  // A human choice, so refresh() runs un-auto'd: it marks the interaction like any click,
  // repaints the stale page, and its first response hits noteAuthedResponse's certain branch
  // (the idle gap exceeds cookie-refresh by construction) — model exact, deadline reset to a
  // full expire.
  refresh();
}

/* The end state — reached from a modeled zero, or "confirmed" when the proxy itself answered
   an API call with its login page. NO automatic probe distinguishes the two: a probe is a
   request, and a request re-stamps a still-live cookie — extending the session with nobody
   present, which is the bug this feature exists to remove. The copy carries the resulting
   uncertainty honestly, and one click recovers either way. */
function sessionEnded(kind) {
  sessionOver = kind;
  $("main").classList.remove("stale");
  const dlg = $("session-dialog");
  $("session-title").textContent = "Signed out";
  // "or is about to": a modeled end is a floor, so the true expiry may be up to cookie-refresh
  // later. The SSO sentence is research Finding 2 — the proxy session ends, the cluster
  // session does not, and a governance page must not imply otherwise.
  $("session-desc").textContent =
    "Your session has ended, or is about to. Nothing more will load until you sign in again — " +
    "and signing in may not ask for a password, because your OpenShift single sign-on session " +
    "is separate and may still be active.";
  $("session-remaining").hidden = true;
  $("session-stay").hidden = true;
  $("session-signout").hidden = true;
  $("session-signin").hidden = false;
  if (!dlg.open) { sessionReturnFocus = document.activeElement; dlg.showModal(); }
  $("session-signin").focus();
}

/* Escape. On the WARNING it is consent to continue, not a dismissal: a keypress aimed at this
   dialog is proof of presence, and dismiss-but-die would manufacture the silent mid-read logout
   the dialog exists to prevent. On the over-state it closes normally — the page behind is dead,
   but still readable and copyable. */
$("session-dialog").addEventListener("cancel", (e) => {
  if (!sessionOver) { e.preventDefault(); staySignedIn(); }
});
/* Focus restore on ANY close path, in one place. The remembered element may have been repainted
   away by the poll; the Refresh button always exists, and landing there beats landing on
   <body>, which is the same silent drop the filter bar's restore machinery exists to prevent. */
$("session-dialog").addEventListener("close", () => {
  sessionLastAnnouncedMs = Infinity;
  const back = sessionReturnFocus;
  sessionReturnFocus = null;
  if (back && document.contains(back)) back.focus({ preventScroll: true });
  else $("refresh").focus({ preventScroll: true });
});
$("session-stay").onclick = staySignedIn;

/* Identity is fetched ONCE: user and logout_url cannot change without the proxy bouncing the
   session, at which point every API call fails over to the signed-out state anyway. A failure
   here (older API, transient fault) just leaves the header plain and the countdown disarmed —
   never a broken page. */
async function initIdentity() {
  const sentAt = Date.now();
  let who;
  try { who = await api("/api/whoami"); } catch (e) { return; }
  if (who.authenticated && who.user) {
    $("whoami").textContent = who.user;
    if (who.email) $("whoami").title = who.email;
    $("whoami").hidden = false;
  }
  if (who.logout_url) {
    sessionLogoutUrl = who.logout_url;
    $("logout").href = who.logout_url;
    $("logout").hidden = false;
    $("session-signout").href = who.logout_url;
  }
  initSession(who, sentAt);
}
```

### 5.4 Interaction with the existing page — checked, not assumed

- The dialog is outside `#main`/`#filters`, the only regions repaints rebuild; its handlers are
  wired once and never re-bound.
- While the modal is open, `showModal()` makes the page inert, so no drill/tab handler can fire

  and their sessions end at ~30m by design; a wall screen wants a per-cluster values override of

```python
class TestSessionModelSoundness:

    one, including the exact sequence that breaks the naive version."""

    def test_a_maybe_restamp_raises_the_floor_but_never_to_now(self, dash):
        """The unsound shortcut — 'assume a re-stamp whenever the MODEL's age crosses refresh' —
        concludes a re-stamp the proxy may not have made and warns AFTER the expiry. The hull
        update must raise the floor only to sentAt - refresh."""
        got = dash.evaluate("""() => {
            sessionOver = false;
            const now = Date.now();
            sessionModel = { expireMs: 1_800_000, refreshMs: 300_000,
                             lo: now - 360_000, hi: now - 60_000 };
            noteAuthedResponse(now);
            return { loAge: now - sessionModel.lo, hiAge: now - sessionModel.hi };
        }""")
        assert 299_000 <= got["loAge"] <= 301_000, (
            f"floor moved to {got['loAge']}ms ago — a maybe-re-stamp must raise it exactly to "
            f"sentAt - refresh, never to sentAt"
        )
        assert got["hiAge"] <= 1_000

    def test_a_certain_restamp_makes_the_model_exact(self, dash):
        got = dash.evaluate("""() => {
            sessionOver = false;
            const now = Date.now();
            sessionModel = { expireMs: 1_800_000, refreshMs: 300_000,
                             lo: now - 400_000, hi: now - 400_000 };
            noteAuthedResponse(now);
            return { loAge: Date.now() - sessionModel.lo, hiAge: Date.now() - sessionModel.hi };
        }""")
        assert got["loAge"] <= 1_000 and got["hiAge"] <= 1_000

    def test_a_provably_young_session_teaches_nothing(self, dash):
        got = dash.evaluate("""() => {
            sessionOver = false;
            const now = Date.now();
            sessionModel = { expireMs: 1_800_000, refreshMs: 300_000,
                             lo: now - 100_000, hi: now - 100_000 };
            noteAuthedResponse(now);
            return Date.now() - sessionModel.lo;
        }""")
        assert 99_000 <= got <= 101_000, "the proxy provably did not re-stamp; the model moved"
```

## 7. The provider=openshift contingency, stated so no work is wasted

If the lab test (research doc, verification step 1) shows `ValidateSessionState`'s query-parameter
token check fails and `cookie-refresh` is unusable:

- **Chart/API lenses**: `-cookie-refresh` is not passed; whoami reports `refresh_seconds: 0`.
- **This lens — nothing is re-coded.** `initSession` disarms on `refresh_seconds: 0` (tested above),
  so the countdown modal goes dormant *as data*, not as a code change. Poll suspension stays and
  stays correct: with an absolute cookie, polls never extended the session anyway, but a suspended
  tab also stops hammering the login flow after expiry and stops burning requests on an empty desk.
  The dead-session failover (§3) becomes the entire end-of-session UX: the first request after the
  absolute expiry surfaces the "Signed out" dialog instead of a parse error. The logout link is
  untouched.
- The only dormant artifact is the warning path — kept in the codebase because re-enabling it is a
  values change, not a release.

## 8. Residual risks, named

- The activity heuristic cannot see a person who only reads, with hands off mouse and keyboard, for
  longer than `IDLE_SUSPEND_MS + (expire − warn)`. They get the modal while present — one click,
  bounded annoyance, and the alternative (counting `pointermove`) re-opens the hole entirely.
- The shared-stamp merge trusts same-origin `localStorage`. Anything able to write it can only make
  warnings *earlier* or *moot-close* them — it cannot move the true cookie expiry, and a same-origin
  attacker is already past every control this page has.
- `redirect: "manual"` assumes the app never redirects `/api/*`. True today (exact FastAPI routes);
  if a redirecting API route is ever added, its responses would read as "signed out" — the api()
  comment states the assumption where the future author will trip over it.
