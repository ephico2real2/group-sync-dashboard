## Findings

### F1a — sibling namespace surfaces still counted `system:` groups (accepted)
**Finding (Grok).** The omit was applied to the listing SQL only. `Snapshot.binding_namespaces` (the
"Observed on a binding" flag) and `counts()["namespaces_with_bindings"]` still did
`FROM rbac_group_binding WHERE cluster_id=?` with no omit. Every real OpenShift namespace carries an
image-puller `system:serviceaccounts:<ns>` group RoleBinding, so a namespace whose only grant is that
built-in would show `Observed: yes` over an empty group-bindings table, and the namespace count would be
inflated — a "confident wrong number about who has access", the product's core failure shape.
**Re-check.** Reproduced: on `e275a5f` a seeded `only-sys` / `system:serviceaccounts:only-sys` binding
put `only-sys` in `binding_namespaces` (`{'(cluster-scoped)','dev-ns','only-sys','prod-ns'}`). The issue
itself requires "apply the exclusion consistently", so this is in scope. The `unmanaged` EXISTS still
reads the raw table, so filtering the outer query changes no surviving finding (C2).
**Decision.** Accepted. `_OMIT_SYSTEM_GROUP_SUBJECTS` appended to the group arm of both surfaces (the
count's user arm also gains the `is_platform=0` that `binding_namespaces` already had — a pre-existing
asymmetry Grok flagged under "not asked"). `binding-findings` drops the `built_in` tier from
`_DEFINITIONS` (it would render a permanent, misleading 0) and its summary no longer claims to mirror the
RBAC-policy tab. Test: a `system:`-only namespace is not observed, not counted, and binding-findings has
no `built_in` tier (fail-before/pass-after).

### F1b — surface a "system:* omitted: N" count in three reports (rejected)
**Finding (Grok).** Extend the existing `platform_user_binding_count` precedent: add
`system_group_binding_count` and print "N system:* omitted" in namespace-access, binding-findings and
compliance-snapshot, so the omission is named rather than silent.
**Re-check.** The mechanism is sound and matches the SA house style. But the operator's #147 rule is
explicit — `system:` groups are **"not needed in reports at all"** — and surfacing a running count
re-introduces the very subject the operator wants gone, across three rewritten `build()` functions.
**Decision.** Rejected on intent and scope. `system:` groups are made *consistently invisible* (F1a),
not counted-and-named. The SA excluded-count note is left as-is (existing behaviour, not in #147's ask).
